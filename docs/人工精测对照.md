## 二、口径差异（不能直接对齐总额，需说明）

人工图的「合计」普遍带两类程序不含的资产，所以**总额无法直接比较**：

1. **预存货**：图里写「424+0 存货」「212+0 存档」，部分图把已有纳贤令/元宝计入；程序默认期初存货为 0，需用户在左栏自行填入。
2. **储值券**：图里的「6488 储」「6488 通」是特定渠道储值，程序只按公告商城档位（¥12/¥30/¥128…）建模，不含储值券。
3. **自选福袋名单里的将**：图中的「张让 / 星袁绍 / 侯成」多来自「纳贤福袋 N 选 1」名单，不是独立可购买目标；程序对这类只做定向产出折算，不作为单独目标报价。

因此人工图标题里的「424 档位」「212 档位」是**围绕储值档位的整体规划总额**，而程序的「需要充值 ¥X」是**本期商城纯购买口径的最少花费**，两者不是同一个量，不能说「对不上」。

## 三、人工图的充值/消费模式（程序已按此逻辑排程）

人工图的逐日模式高度一致，程序逐日排表已按此实现：

```
充值：30+12 / 12+12 / 328+12 组合，集中在前几天
消费：每日冲到 20000 或 28888 档位（首日 8888 福利券）
券购：用 1k/1888 抵价券买纳贤令、锦绣
副产物：草人（充值/消费/游戏产）→ 箭矢 → 概率武将
```

在程序的「每日方案表」里可以看到对应的逐日充值、当日消费命中档位、券购道具、草船覆盖表——这就是人工图排表的程序化版本。配合「充值分析 → 自己配」勾 30+12 这类组合，可复现人工图的充值结构。

## 四、想进一步对齐的话

如果需要把某张图的**具体金额**也变成程序必须命中的断言，需要先把图里的储值券/预存货口径转成程序参数（期初存货 + 储值档位），这部分公告里没有、是账号级信息，暂时无法自动建模。可针对单张图手工录一组「期初存货 + 目标组合」作为回归样本，但那属于定制口径，不建议作为通用基准。
