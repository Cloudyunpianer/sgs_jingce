## 改了什么

### 1. 品类归一（新增 `js/currency.js`）

公告每期换名字：寒露夺宝券 / 重阳夺宝券 / 秋华夺宝券 / 初冬夺宝券…… 全部收敛成引擎认识的品类 key（内部沿用 `狂欢夺宝券`、`狂欢水晶球`），展示层再用 `P.curLabel` 还原成本期叫法。

抵价券按面额拆 key：`券2500 = {face:2500, min:3000}`，不再是写死的 `券1111/券2888/券6665`。

### 2. 解析器重写（`js/parser.js`）

- **去专名**：夺宝进度从 `累计参与狂欢夺宝` 改成 `累计参与(.+?)夺宝`，5/6 期的转盘进度不再丢失。
- **表头泛化**：商店按「表头形状」识别而不是按店名——如意商城认「兑换所需」、锦绣认「兑换价格」、宝玉认「消耗宝玉」、水晶球认「水晶球」。秋华的如意商城（17 项）和皮肤直售（20 项）第一次被正确读出。
- **补 6 个解析块**：限时商品/免单商城（购买渠道）、单笔充值、累计充值、充值返券、每日消费、累计消费。这是精测最核心的输入，之前 0 覆盖。
- **充值档位合并**：双十一的「额外赠」段（同一档位追加券）并入主档；「仅限 11/7」「11/8 起」分别记 `onlyDay` / `fromDay`，不再当成两个互斥档。
- **直充兜底**：档位总额不足以覆盖需求时，余量按 1 元 = 100 元宝直充，不再返回「¥0 无解」。
- **无渠道标记**：某品类本期买不到（如秋华没有珍宝礼盒，宝玉只能靠消费送），输出 `unbuyable`，UI 明确提示，而不是算成 0 元。

### 3. apply 改为「先清空后填充」

解析不到的 `systems` / `shops` / `coupons` / `chargeTiers` 一律置空，并在返回的 `log` 里写明「已清空」。

改造前导入寒露，`PRESET.systems` 里还挂着双十一的三个礼盒、19 档祈福、三个转盘、16 个签筒、锦绣与水晶球商店。现在导入后只剩本期真有的：纳贤 + 两个夺宝转盘。

同时清掉 `SCHED` 的商品目录缓存——这个缓存不清，换期后价格表会沿用上一期。

### 4. 白送口径修正

以前所有「登录天数」表都被当成白送，但那些表是**买了勋章之后**的领取清单：

| 期 | 福利勋章 | 钜惠勋章 |
| --- | --- | --- |
| 寒露 | 5888 元宝 | 12888 通用元宝 |
| 双十一 | 6888 元宝 | 13888 通用元宝 |

现在按表头区分：

- 表头 `天数` → 活跃任务，**真白送**，进 `freeGains`
- 表头 `登录天数` / `累计登录` → 需先买对应商品，进 `boughtGains`，并带上价格

寒露期实测：改造前白送「纳贤令×23、招募令×20」，改造后白送纳贤令×1（活跃任务），另外 4 条勋章产出被标为「需购买」。

### 5. plan.js 去硬编码

- 商品目录按 `kind` 映射，不再认 `db_ljjp/db_wcz/db_fc` 这种本期 id
- 夺宝需求从 `P.systems.filter(s => s.kind === 'gacha')` 取，不再写死三个 id
- 券的抵扣顺序按面额动态排序，`cpnKeys()` 跟着 `P.coupons` 走
- `build()` 的券迭代不再写死三个 key

## 秋华为什么没有价格

秋华期**没有珍宝礼盒**（`## 四、传世宝玉` 只有「消费送宝玉」：累计消费 3 万/6 万/10 万给 3+3+4 玉）。而宝玉商店里 25 玉的目标，靠消费只能拿到 10 玉。

工具现在会显示：

```
无渠道：礼盒×7000
```

而不是像以前那样静默给一个 ¥0 的方案。这是数据事实，不是解析失败——把公告里所有礼盒段落都扫过了，确实一个都没有。

## 还没做的

| 玩法 | 出现期 | 状态 |
| --- | --- | --- |
| 群英绘卷（碎片合成皮肤） | 重阳、立冬 | 识别到活动名，未建模 |
| 幸运砸蛋（绿/紫/金蛋 + 幸运币） | 重阳 | 同上 |
| 欢乐连连看 | 秋华 | 同上 |
| 福喵纳财 | 初冬 | 同上 |
| 积惠特卖 | 立冬 | 同上 |

这五种都是「皮肤/外观」玩法，不影响「武将花多少钱」这个主问题，但确实算不出来。解析器会把它们列进 `unsupported`，导入弹窗里明示「未纳入精算」。

另外：

- **累计充值档位**解析出来了（`P.cumCharge`），但只做展示，没有参与最优解计算。因为累充奖励多是宝箱类，折算价值主观。
- **专属纳贤令**（谋钟会纳贤令这类）记为 `only` 项，不参与通用抵扣。
- **内置双十一数据**仍是手工口径（勋章产出算白送、勋章价格未计入成本）。这是历史口径，改了会动 768/262/614/280/328 五个基准值，所以没动。导入当期会用严格口径，两者会有差异——已知差异，写在 README 的「它不做什么」里。
