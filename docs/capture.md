# 油猴内嵌精测台（抓包 + 导入）

一个 Tampermonkey（油猴）脚本（脚本名：**吾亦能善算谋划**），把**完整精测程序**嵌进三国杀官网页面里运行：hook 后台请求抓到活动 JSON，转成公告文本，一键导进内嵌的精测程序，当场出结果。

打开官网页面**不会自动弹出**精测台，只显示一个右下角小浮窗，点它才全屏打开；进去后点「⚡ 一键导入本期活动」即可傻瓜式导入，不用选抓包条目。

**你要版本管理的是脚本文件本身**（`tools/capture/` 下的源码和产物都随仓库提交）。脚本不写磁盘、不连本地服务、不碰 git。

## 一、文件与构建

| 文件 | 作用 |
| --- | --- |
| `sgs-jingce.template.js` | 油猴脚本**源码模板**（改这里） |
| `embedded.html` | 精测程序的单文件版（HTML+CSS+9个JS 全内联），构建产物 |
| `sgs-jingce.user.js` | **最终安装版**（把 embedded.html 内联进模板，389KB，脚本名「吾亦能善算谋划」），构建产物 |
| `build-embedded.js` | 构建脚本，一条命令重新生成上面两个产物 |

改了 `index.html` / `style.css` / `js/*.js` 或油猴模板后，重跑：

```bash
node tools/capture/build-embedded.js
```

它会：① 把精测程序打包成 `embedded.html`；② 把该文件内联进模板生成 `sgs-jingce.user.js`。

> 为什么要把整个精测程序内联进油猴脚本：油猴运行在 `https://x.sanguosha.com`，浏览器不允许它 fetch 本地 `file://` 文件；而精测程序是纯前端静态页。内联成自包含字符串、用 iframe `srcdoc` 承载，是让它"在油猴里跑"又不依赖本地服务的唯一自包含方式。

## 二、安装与使用

1. 浏览器装 Tampermonkey / Violentmonkey。
2. 把 `tools/capture/sgs-jingce.user.js` 拖进浏览器安装。
3. 打开三国杀官网活动后台页面，右下角出现一个「⚡ 精测」小浮窗（**不自动弹出**，不打扰浏览）。**浮窗可按住拖动**到任意位置，位置会记住，下次打开还在原处。
4. 点浮窗 → 全屏打开「内嵌精测台」：
   - **顶部工具条**：醒目的「⚡ 一键导入本期活动」按钮 + 状态提示。
   - **下方主体**：完整精测程序（选将、倍率表、每日方案等，功能与本地打开一致，全屏铺满）。
   - **抓包详情**（默认折叠）：抓包列表 + 公告文本框 + 导入/复制/下载按钮，需要时点顶栏「▾ 抓包详情」展开。
5. 傻瓜式用法：进页面后 hook 已在后台跑 → 点「⚡ 一键导入本期活动」→ 脚本自动从抓包里挑最像本期公告的一条转成文本导进去 → 精测程序自动 `PARSER.parse` + `apply`，当场刷新出本期结果。选将 / 计算仍在精测界面里手动做。
   - 若想自己控制：展开「抓包详情」，点某条抓包或直接在文本框粘贴官网公告 md，再点「导入下方文本」。
6. 关闭面板后浮窗回到右下角；油猴菜单命令「打开内嵌精测台」也可随时唤回。

## 三、要在哪里抓？（重要）

**网页版三国杀（`web.sanguosha.com`）本身就是浏览器页面，脚本在它上面照样能跑**——打开游戏页右下角就会出现浮窗，不需要"再去官网"。原生客户端（PC/手机 App）才是油猴碰不到的。

但要区分一个关键：**"脚本能跑" ≠ "当前页面有公告数据"**。精测要的是充值档位 / 纳贤进度 / 奖励表格这类**公告正文**，而不是福利配置。

- ✅ 能抓：只要页面上**把公告正文显示出来**——不管是官网公告详情页（`x.sanguosha.com/news/…`），还是网页版游戏里点开的活动公告弹窗/页面。脚本有两条通道：
  1. **抓包通道**：hook 页面发出的 JSON，含公告正文的响应会被识别（URL 无需带 activity/news 关键字，默认抓全部 JSON，靠公告特征筛选）。
  2. **页面文本通道**：若公告是 HTML 渲染、不走 JSON 接口，脚本会扫描主页面及同源 iframe 的可见文本（`innerText`），按公告特征评分取最优。
- ❌ 抓不到也导不进：活动的**配置/福利**接口。例如：

  ```json
  { "day_gifts": [{"gift_name":"稀有将印宝箱","num":7,...}],
    "add_gift_config": {"item_id":"710123,288;...","gift_1_num":288,...},
    "qywx_friend_days": 229, "add_gift": 2 }
  ```

  它只有登录天数礼包、加赠礼包、企微好友天数——**没有充值档位、没有纳贤进度、没有武将池**。这类数据会被标记为「配置」，不覆盖文本框、不参与导入。

**正确操作**：在游戏页里点开本期的活动公告（充值/纳贤说明），让公告文字**显示在屏幕上**，再点「一键导入」。脚本会抓包 + 扫页面双通道找公告，按「单笔/累计充值…元宝」「累计纳贤」「可领取奖励」「限完成N次」「奖励表格」等特征命中数评分，挑最像公告的一份导入（命中 < 2 项则拦下并提示）。

> 定位技巧：展开「抓包详情」，列表里 `✓公告` 绿色的就是识别到的公告数据，`配置` 灰色的是福利/礼包等无关数据；状态栏会显示"抓包 N 条，其中 M 条公告"。若全是「配置」，说明公告正文还没在页面显示出来，先去点开公告。手动粘贴的内容只警告不拦（尊重非标准格式）。

> 兼容说明：从网页 copy 的正文没有 markdown 的 `#` 标题前缀、表格是 tab 分隔，解析器已兼容（标题按"含 M.D-M.D 日期范围的行"兜底识别）。导入后请把精测台顶部的**活动标题 + 日期**一起核对——两者都变成新期才算真正导入成功。若只有日期变了、标题还是旧期，说明喂进去的是被截断/夹杂导航的残缺文本，请重新完整复制公告正文再导。

## 四、改成抓真实接口（拿到样例后要做的）

两处可配置，都在模板 `sgs-jingce.template.js` 顶部：

```js
var CAPTURE = {
  urlPatterns: [],  // 默认抓所有 JSON：网页版游戏接口地址不含关键字也不漏，靠公告特征筛选
  minSize: 200,     // 小于该字节数的响应忽略（默认 200，别把真实小响应过滤掉）
  maxKeep: 80
};

var TRANSFORM = null;  // JSON → 公告文本钩子
```

- **接口地址**：默认 `[]` 抓所有 JSON。若只想抓特定接口，可填路径关键字（例如 `/api/activity/detail`）。留空最稳，配置数据会被公告体检自动过滤掉。
- **JSON → 公告文本**：默认走通用展平 `jsonToText()`（找 `content/markdown/md/text/...` 字段，或整对象转文本）。拿到真实 JSON 样例后，把 `TRANSFORM` 写成精准转换，例如：

  ```js
  var TRANSFORM = function (payload, url) {
    return payload.data.activityNotice; // 按真实结构调整
  };
  ```

  返回的是**公告 markdown 文本**，交给精测程序的 `PARSER.parse`。若接口直接返回的就是公告 md 字符串，可留默认。

改完模板后记得重跑 `node tools/capture/build-embedded.js` 重新生成安装版。

## 五、验证过的链路

- `embedded.html` 直接打开：133 个目标卡片正常渲染；`__SGS_IMPORT__(公告文本)` 导入真实小雪样本，充值档与活动信息正确更新，零 JS 错误。
- 油猴脚本注入到模拟后台页：进页面只显示浮窗（面板不自动打开）、浮窗可拖动且拖动不误开面板、点浮窗后全屏面板 + iframe 渲染、hook 生效、抓包 → 清空文本框后点「一键导入本期活动」自动挑抓包 → postMessage → 内嵌精测返回「已导入并刷新」、活动信息从旧期更新为新期、关闭面板浮窗重现，全程零 JS 错误。
- 网页版游戏页场景（`web.sanguosha.com`）：福利配置 JSON 被标为「配置」、不覆盖文本框、不参与导入；真公告即使 URL 无 activity/news 关键字也按公告特征命中数（7 项）被选中并导入；清空抓包后改为扫描页面 HTML 可见文本，同样命中公告并导入成功。全程零 JS 错误。
- 公告体检：命中 < 2 项公告特征的数据被拦下并提示「未找到公告正文 — 请点开活动公告或粘贴公告文本」。
- 项目回归 304 项全绿。

## 六、说明

- 精测程序在 iframe（`sandbox="allow-scripts allow-same-origin"`）里跑，与官网页面的 DOM/CSS 隔离，互不干扰。
- 数据注入走 `postMessage`，消息带 `__sgsCapture:1` 标记，精测程序校验后才处理，避免误收页面其它消息。
- 抓下来的临时数据不建议提交；要留样例放到 `samples/` 并确认无账号等敏感信息。
